# 相邻的内核版本，布局并不相邻

> 状态：未成功。一次内存态临时 root 的版本移植尝试，以及它暴露出的方法问题。

设备：vivo iQOO Neo9S Pro（V2339FA / PD2339）
内核：6.1.124
结果：五次实测全部崩溃，失败点已定位，判定该方向在当前条件下不可行。

## 一句话

想把一个内存态临时 root 方案从较新内核搬到低一个版本上。手上没有目标版本的镜像，于是找了两台内核跨度一致的参考机，用它们的差值外推。

五次实测，五次崩溃。事后看，失败的原因不在偏移算错，而在方法本身——我以为内核版本相近，内存布局就相近。这个假设在两台参考机之间就已经被证伪了。

## 结论

前两层都过了。

符号解析与内核基址定位成功，九个关键符号全部解析正确。写原语本身也是干净的——用构建自带只读模式跑完十五轮、四百多次系统调用，零崩溃。

第三层崩溃。两次换候选值、一次换传输路径，全部崩在同一处。

真正卡住的是一个栈帧深度常量：符号表里没有它，没有镜像反汇编不到它，相邻版本也外推不出它。而前面花力气推导的那些全局符号，其实从来不是瓶颈。

## 风险实况

五次失败全部表现为内核崩溃后自动重启，没有例外。

全程不写入任何分区，不修改 Bootloader，不触碰校验相关分区，不解锁引导，不改动 A/B 槽。写原语的落点被限制在内核数据段范围内，而这段物理内存被内核在启动早期保留，不会分配给文件缓存使用。

实际代价是一次黑屏重启，加上可能丢失尚未落盘的数据。设备本身没有被打坏，五次之后依然原样开机。
